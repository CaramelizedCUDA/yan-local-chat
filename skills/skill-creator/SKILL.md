# 技能创建器

和用户一起把想法、已有流程或反复出现的工作写成可复用技能。默认用中文，先做够用的版本，再根据真实使用改进；不要为了创建技能而引入整套工具链。

## 1. 明确要解决的事

先从对话和已有材料提取：
- **目标**：技能帮助完成什么，不负责什么。
- **使用时机**：用户会怎样提出需求；哪些相近请求不该触发。
- **输入与输出**：会收到什么材料，最终需要正文、文件还是其他结果。
- **关键限制**：格式、质量标准、工具依赖、隐私和需要用户决定的事项。

已有答案不重复问。只在缺少的信息会影响做法时询问，通常一次问 1–3 个关键问题。用户只想先写一个草稿时直接起草，不强制访谈或测试。

如果用户说“把刚才的流程做成技能”，提炼其中稳定的步骤、纠正和验收标准，不把本次临时路径、一次性数据或偶然错误固化进去。

## 2. 写出最小可用草稿

默认一个目录里只放一份 `SKILL.md`：

```text
技能名/
└─ SKILL.md
```

文件使用 UTF-8，开头是 YAML 元数据，后面是 Markdown 指令：

```markdown
---
name: meeting-notes
description: 把会议录音转写或零散笔记整理为纪要，提取决定、待办和未决事项。用户要求写会议纪要、整理会议笔记或从讨论中提取行动项时使用。
---

# 会议纪要

阅读全部材料，按议题整理讨论、决定、待办和未决问题。
待办列出负责人和时间；原文未说明的标为“未明确”，不要猜测。
区分提议与已确认决定，不把讨论意见写成承诺。
默认输出可直接发送的 Markdown 纪要。
```

编写时注意：
- `name` 与目录名一致；新技能优先使用简短、小写、短横线名称，已有技能无须随意改名。
- `description` 写清“做什么、何时用”，包含用户的自然说法；不要堆无关关键词，也不要把所有任务都圈进来。
- 正文说明步骤、判断条件、输出要求、常见例外及完成前检查。触发范围主要写在描述里。
- 解释重要规则的原因，优先用清楚可执行的指令，避免口号和大量重复的强制词。
- 有明确格式要求时给一个短例子；事实缺失时注明未知，不用例子里的内容冒充事实。
- 不重复整份宿主系统说明；工具和路径以当前环境为准，不凭空假设有 Claude CLI、Bash 或特定模型接口。
- 默认保持单文件。只有确实重复使用的代码、较长参考或模板才拆为 `scripts/`、`references/`、`assets/`，并说明何时读取或调用。
- 技能不能扩大授权范围，不因其中写了指令就自动外发资料、发布内容、删除文件或安装依赖。

## 3. 用真实例子检查并改进

先检查文件本身：元数据可解析，名称与描述非空，目录与名称一致，没有悬空引用、互相冲突的要求、敏感信息或错误的环境假设。

再按任务需要决定是否试跑：
- 简单草稿或用户只要文件：交付即可，说明尚未做实际试跑。
- 可客观检查的任务：建议 2–3 个贴近真实需求的例子，覆盖常规输入、信息缺失或边界情况；先与用户对齐测试范围。
- 主观创作任务：侧重实际输出和用户评价，不硬凑量化分数。

测试时把输入、实际输出、检查标准和发现的问题对应起来。需要委派时，提供完整任务和所用技能；只有能保证环境相近且基线不接触被测技能和结果时，才声称进行了有技能／无技能对照，否则称为试跑或人工检查。

分清四件事：文件已保存、结构检查通过、任务已实际执行、效果获得用户认可。不能相互替代。依赖缺失、超时或解析失败记为“错误”或“未运行”，不能算通过；没有测到的耗时、token 和触发率不编造。

把结果直接展示给用户即可，不强制生成评审网页。根据反馈修改通用规则，而不是只为某一个例子加补丁。保留有用步骤，删掉造成重复、误解或无谓耗时的要求，再视需要复测。用户满意或明确结束时停止。

描述也可以用几个“应该使用”和“相近但不该使用”的请求人工审阅；没有真实自动评测就不声称测出了触发率。

## 4. 保存与交付

在言中，一份技能是技能目录下的文件夹及其中的 `SKILL.md`，不是必须导入的 `.skill` 文件。技能根目录见系统提示里的技能目录。

- 用户只要草稿时，按要求在对话展示或交付文件，不擅自安装。
- 用户要求创建并使用时，写到 `<技能根目录>/<name>/SKILL.md`；操作前检查同名内容，避免误覆盖。
- 修改已有技能时保留名称，按用户要求处理旧文件和备份；未经要求不要顺手清理无关文件。
- 临时脚本、测试材料和中间文件放本轮指定的卷宗草稿目录；需要下载的成品放卷宗根目录。
- 不默认打包 `.skill`。它是归档包，不是言直接读取的格式；只有用户需要备份或迁移时再打包，并先排除凭据、隐私、缓存和临时产物。
- 安装或修改后通常下一问生效；当前问可以手动读取，但不把手动读取说成已验证自动触发。

交付时简要说明：技能名称、保存位置、如何点名使用，以及实际完成了哪些检查。例如：`用技能创建器，把这套报表流程做成技能`，或从输入框「＋」→「技能」里挑它，再写需求。
