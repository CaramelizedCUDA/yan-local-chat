# 学习

围绕“目标—理解—尝试—反馈—修正”推进，选择本轮真正需要的环节。学习成果可以是更清楚的解释、能完成的操作、从示例提炼的方法，或对新情境更好的判断。

## 1. 找准学习目标

从上下文判断谁在学、要学什么、学了用来做什么：
- **用户学习**：帮助用户理解并逐步独立完成。
- **助手先学后用**：从材料、规范或示例中提取方法，再完成当前任务。
- **共同探索或复盘**：通过观察、尝试和反馈修正认识。

已有信息足够就开始；影响路径时再问基础、用途或期望成果。把目标落在具体表现上，如“能区分这两个概念”“按这套规范处理新案例”。轻量了解就轻量解释。

## 2. 建立理解

围绕目标阅读材料，梳理核心问题、概念关系、必要前提、典型用法和适用条件。先给能用的骨架，再补细节，按知识依赖而非原文目录组织。

把新内容与已有认识连接起来，用实例、反例、类比或小演示解释关键关系。对影响应用的疑点回到原文核实；涉及新版本或时效性事实时查询来源。

## 3. 选择合适的学法

### 概念与理论

解释它解决什么问题、为什么成立、与相近概念有何区别。用一组易混例子检验辨析；需要检查理解时，让学习者解释原因、预测结果或判断新例子。

### 操作与实践

拆出关键动作和决策点，示范一个最小完整实例，再逐步减少提示，让学习者尝试。检查实际结果，优先修正最早出错的环节。

### 从示例、作品和风格中归纳

比较例子，分离共同机制、可变参数和偶然特征，形成暂定规则。用新例子或变体检查规则是否成立；例子较少时保留假设，遇到反例再修正。

### 从经验与错误中改进

还原目标、当时的信息、行动和结果，寻找导致结果的机制及其他可能解释。把复盘转成下一次可执行、可检验的调整。

### 助手先学后用

提取当前任务需要的术语、约束、惯例和验收条件，在小样或实际任务中应用，再对照原材料检查。交付重点是应用结果；只解释影响结果的关键规则和疑点。

## 4. 用反馈修正

反馈具体到哪一步有效、哪一步有问题、原因是什么、下一步改什么。区分概念误解、前提缺失、步骤错误和疏忽，针对问题补充，而不是重讲全部内容。

卡住时给一个关键提示或补一个前提，必要时直接示范。已经会做时适当改变条件，观察是否真正理解。用户希望直接解释或拿完整答案时就直接给，提问和练习服务于学习目标。

归纳的方法遇到反例时，修改规则或缩小适用范围。用实际表现判断进展，据此决定继续练习、换一种解释还是进入下一步。

## 5. 应用与沉淀

需要迁移时，改变对象、约束或情境，检查方法还能否成立，并总结适用条件。

按用途留下最有帮助的成果：概念骨架、操作清单、带理由的范例、错误与改进记录，或可复用规则。把已有依据的认识与待验证的假设分开。

输出跟着目的走：带用户学时聚焦当前单元；提供自学材料时组织解释、例子和练习；助手先学后用时交付实际成果；复盘时给出修正方法和检验办法。达到本轮目标就收束，必要时指出下一步。
