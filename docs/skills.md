# 技能

[← 文档目录](README.md)

一份技能是一个目录，里面有一个 `SKILL.md`：头上用 YAML 写 `name` 与 `description`（做什么、何时用），正文写怎么做，同目录可另附参考文档、模板与脚本。写法与 Claude Code 的 skills 相同，现成的技能拷进来即可用。

- **放在哪**：言认三处——存储根的 `技能/`（默认 `~/.yan/技能/`，设置 → 工具里写着实际位置）、`~/.claude/skills`，以及工作目录的 `.claude/skills`（只在绑了这一目录的对话里认）。技能目录可以隔着一两层（如 `~/.claude/skills/某组/某技能/SKILL.md`），点开头的目录不认。同名的，工作目录的为准，其次存储根，再次 `~/.claude/skills`。
- **模型怎么用**：不另设工具。技能是「翻阅文档」（`read_document`）的又一路来源：各技能的名字与 `description` 列在这件工具的说明里，模型做到相关的事先凭技能名翻 `SKILL.md`，再按说明以「技能名/路径」翻同目录的参考；翻到的 `SKILL.md` 开头注明技能目录，在行里要跑技能自带的脚本就照这个目录。言、行、旁注与帮手都翻得到。
- **何时生效**：每一答开工前重扫一遍，放进去、改过、删掉的下一问就认。只有 `description` 进说明，正文用到才取，技能多了也只多几行。
- **开关**：设置 → 工具 → 技能里逐份勾选，勾上的才给模型。`~/.claude/skills` 里的默认不勾——那里多是为别家写的（如 Claude 桌面端的技能，讲的是言没有的工具），说明又长，每一问都要带着；要用哪份勾上即可。存储根与工作目录里的是特意放进来的，默认勾上。
- **预设**：没挑「翻文档」这一组的预设，连同技能一并不给。
