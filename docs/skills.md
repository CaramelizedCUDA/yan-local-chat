# 技能

[← 文档目录](README.md)

一份技能是一段用到才看的做法：名字、何时用、正文。它存作一个目录，里面有一个 `SKILL.md`，头上用 YAML 写 `name` 与 `description`（做什么、何时用），正文写怎么做，同目录可另附参考文档、模板与脚本。写法与 Claude Code 的 skills 相同，现成的技能拷进来即可用。

- **写一份**：设置 → 技能 → 存储根，点「＋」就地写名字、何时用与正文，焦点离开即存成 `技能/<名字>/SKILL.md`；行末的「改」就地改（改名时目录跟着改，头上别的几项原样留着），摊开后「删去」连同目录里的脚本与参考一并删掉。另两处是别家的目录，只看只开合。
- **放在哪**：言认三处——存储根的 `技能/`（默认 `~/.yan/技能/`，设置 → 技能里写着实际位置）、`~/.claude/skills`，以及工作目录的 `.claude/skills`（只在绑了这一目录的对话里认）。技能目录可以隔着一两层（如 `~/.claude/skills/某组/某技能/SKILL.md`），点开头的目录不认。同名的，工作目录的为准，其次存储根，再次 `~/.claude/skills`。
- **模型怎么用**：不另设工具。各技能的名字与 `description` 列在系统提示里，模型做到相关的事先用「翻阅文档」（`read_document`）凭技能名翻 `SKILL.md`，再按说明以「技能名/路径」翻同目录的参考；翻到的 `SKILL.md` 开头注明技能目录，在行里要跑技能自带的脚本就照这个目录。技能的文件整份给（至多六万字），不像长文档那样只给开头。言、行、旁注与帮手都翻得到。
- **人点名用**：问话以 `/技能名` 开头（如 `/写信 给房东说退租`），发出前那份说明就作一件附件随这一问附上，模型不必再去翻；关着的技能也认。名字对不上的照原话发。
- **行迹**：翻技能的那一步标作「技能」，题写技能名。
- **何时生效**：每一答开工前重扫一遍，放进去、改过、删掉的下一问就认。只有 `description` 进系统提示，正文用到才取，技能多了也只多几行。
- **设置 → 技能**：左列三处来处（工作目录那一处看眼下这段对话绑的目录，没绑不列），右列一份一行——名字、说明的头一句、带几件脚本与参考，开着的一笔勾。点一行即开合，开着的才给模型；「打开」在文件管理器里打开那一处。`~/.claude/skills` 里的默认关着——那里多是为别家写的（如 Claude 桌面端的技能，讲的是言没有的工具），说明又长，每一问都要带着；要用哪份点开即可。存储根与工作目录里的是特意放进来的，默认开着。
- **预设**：没挑「翻文档」这一组的预设，连同技能一并不给。
