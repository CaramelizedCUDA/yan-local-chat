# Attachments and Files

[← Docs](README.md) · [中文](../files.md)

- Click, drag in or paste images, text, code, PDF, Office and other files. PDF, DOCX, PPTX, XLSX and the like have their text extracted locally in the browser first; images are sent as visual content; other binary files use the compatible API's file content format
- Attachment originals are stored with the chat in the storage folder's `附件/` (if writing to disk fails, they wait in the browser's IndexedDB and are pushed into the folder once the bridge reconnects). Up to 32 MB per file, at most 10 files and 64 MB per send; originals nobody uses any more (chat deleted, attachment removed) are cleared after a day. Files saved into Files can be up to 256 MB each. The PDF parser and CJK character maps ship with the project
- **Files** (卷宗) keeps frequently used files across chats. Files is the storage folder's `卷宗/` (by default `~/.yan/卷宗/`), and the Files page is a view of that folder. Files dragged in (only from outside the page; dragging an image within Files or an attachment in the input area doesn't save another copy; dragging in a folder recreates it as is, renaming duplicates and skipping names starting with a dot; the input area takes only files, so drop folders into Files), files saved with **Save to Files**, and outputs the model writes in chats with no bound folder all land here. You can preview, download and delete them. To send one with a message, choose **Files** from the input box's **＋** (web pages and script files are always shown as plain text in a sandbox, never run with this site's identity). Scripts and intermediate files the model writes to produce an output go in a hidden folder `.草稿/<chat id>/` inside Files, which the page doesn't list; they're cleared when the chat is deleted, and the top of the Files page also offers "n scratch folders · size · Clean up". Outputs made in one Chat-mode answer (files newly created or changed in the root of Files during that answer) hang on an outputs card at the end of the answer, one line each — type, file name, size, with **Preview** and **Download** on the right. If you later delete one from Files, its line stays but is marked **Removed from Files** and loses both buttons. **Preview** is an in-place floating preview, no download needed: images shown directly, PDFs in the browser's built-in reader, CSV / TSV as tables, Markdown rendered, text and code as is, Word / Excel / PPT with text extracted locally, web pages in the same isolated sandbox as in-page visuals; every file on the Files page has this **Preview** too. Documents in Files (PDF, Office, text) are readable from every chat in both modes: the model reads them with `read_document`, fetched and extracted locally only when used; this can be turned off in settings. **Export** in a chat's **⋯** menu in the sidebar saves the whole chat as Markdown (with step summaries and outputs) into Files. Search by name and filter by image / document / audio / video / archive; deleting a chat never deletes its outputs from Files
- Listen: clicking **Preview** on audio in Files or in attachments opens the audio player — a track drawn as a single brush circle (ensō), the stroke thickening and thinning with loudness, the brush tip marking the present; previous and next track (audio in the same place forms a list, playing on to the next, and wrapping to the first after the last). Clicking outside or pressing Esc minimizes it: the music keeps playing, and a thread of ink drops from the top right of the text with a small circle that sways with the sound; click it for a paper tag (title, time, previous / next, play / stop), and click the title to return to the full view. Only the × on the full view stops playback. There is a single resident player on the page; anything else that wants to play audio just hands a track to `listenLoad` (`src/25-listen.js`)
- In a multi-turn chat, only the message being answered carries attachment originals. Text and extracted content in earlier messages become summaries (truncated past 3000 characters), and images and binary originals become placeholder notes. To let the model see an old image again, attach it from Files again
- Text attachments and extracted content in the current turn also have a cap: about 15% of the model's window (24k tokens if no window is set). Anything larger is sent only as one line, "file name, character count", and the model reads it by page or keyword with `read_document` instead of stuffing a whole book into the prompt and overflowing the window. A character-count estimate is recorded when the attachment is stored, and the context counter at the lower right uses it
